# 看板缓存、加载与人员统计

状态：第一阶段已实现。适用于当前 Jira 6 工作台、本地代理及内置 MCP。本文记录实际行为和后续边界。

## 目标与改动

减少重复查询、限制请求峰值、让先返回的列先显示。未修改 Jira 接口和数据库，不在没有实测的情况下承诺首次加载缩短多少。

原看板最多六列一起查询，等待全部完成后显示。现在仍保留每列准确总数和前60条的查询语义，改为共享有限队列、逐列显示与独立重试。统计使用单独的完整范围分页，不能将六列前60条的并集当成全量。

## 当前参数

| 参数 | 实际值 | 含义 |
| --- | --- | --- |
| 同一代理上游总并发 | 默认2，可配置1–4 | `WB_JIRA_CONCURRENCY`；HTTP、MCP、读取、写入和附件共用 |
| 后台统计补页并发 | 1 | 前台首屏和交互优先，后台等待超过5秒后提高排队优先级，仍最多一路 |
| 最大等待队列 | 100 | 超出返回503，避免无限堆积 |
| 搜索结果新鲜期 | 60秒 | 成功完整读取后计时；详情20秒，项目列表60秒，元数据5分钟 |
| 看板旧结果可展示期 | 最长5分钟 | 按项目和筛选隔离；过期后同步，失败明确提示 |
| 看板筛选防抖 | 300毫秒 | 标题输入另有350毫秒防抖，切换后取消旧等待 |
| 卡片每列条数 | 最多60 | 超限提示用筛选缩小范围 |
| 统计每页/总上限 | 100 / 1000 | 串行分页、间隔100毫秒；显示已加载/总数和完整性 |
| 前端快照 | 内存最多8份 | 当前标签页 sessionStorage 总序列化大小约100万字符；超出淘汰旧快照 |
| 代理成功缓存 | 最多1200条、32MB响应体 | 超限淘汰已完成结果，执行中的请求继续合并 |
| 定时自动刷新 | 关闭 | 手动刷新和页面重新聚焦时核对；连续聚焦节流1.5秒 |

降低并发会降低峰值，冷启动总耗时不一定缩短。此上限只约束当前代理进程，不能约束多台电脑共同访问 Jira 的总并发。浏览器取消等待也不代表 Jira 已停止数据库查询。

## 前端查询与快照

`src/lib/board.ts` 负责必要字段、规范化 JQL、类型归类及按账号计数。多选类型和阶段排序后形成查询身份，人员用用户名识别，显示名不改变身份。字段和排序固定在看板协议中，结构版本在存储 key 中。

`src/lib/useBoardData.ts` 按 Jira 地址、登录账号、项目和规范化 JQL 隔离快照。退出或收到401时清除前端缓存；新的登录会话通过代理数据代次重新校验旧快照。

- 60秒内：立即显示同范围快照，只请求本机 `/api/cache/status` 核对数据代次，不查询 Jira。
- 60秒至5分钟：保留同范围旧内容并显示同步状态，更新需要刷新的列和统计。
- 超过5分钟、项目代次改变或无快照：重新加载，不借用其他筛选、人员或项目的数据。
- 单列失败保留该列旧结果并显示错误，成功列继续可用；重试时仅重查失败或过期的列。
- 手动“刷新看板与统计”绕过前后端已完成结果缓存。执行中的相同读取继续共享；写后已移除的旧代次不能回填。
- 正在核对、过期或失败的卡片禁止拖拽。流转时实时读取可用 transitions，Jira 负责最终权限和工作流约束。

## 人员筛选与统计

人员筛选覆盖看板、需求树和全部问题。通过 Jira 只读用户搜索查询姓名或账号，300毫秒防抖、取消旧搜索；可连续搜索勾选多人、查看已选和移除，点“应用”后统一查询。所选任一账号匹配经办、开发、测试任一字段即纳入，与“只看我的”互斥；取消或关闭弹层不改变已应用条件。旧单人配置自动迁移，筛选、已保存视图和分享链接均支持多人。

统计面板跟随项目、影响版本、模块、阶段、类型、人员、标题/编号和隐藏历史已结束等公共筛选。首屏列完成后才启动后台补页；收起停止继续补页，再展开可复用和续读未过期的已读结果。

- 两张环形图：需求分布，以及任务分布（可切换 Bug）。任务仅包含编码任务和其他任务。
- 经办人、开发人员、测试人员三种归属，每个问题按所选字段唯一归属；同名账号分别计数，空字段归“未分配”。
- 父需求和子任务各计一项；问题数占比不代表工时，也不将 Bug 混入任务。
- 每图前五位、其他人员、未分配；“其他人员”保留原账号集合，可以下钻。
- 全员对照表保留全部账号，可查看各类型明细；图例、扇区、表格数字均能打开只读列表，再打开问题详情。
- 切归属、切右图类型、查看明细、排序和导出均基于同一已加载数据集，不额外按人员发 Jira 查询。
- 分页中显示“正在补齐”，未完整时图表明确基于已加载结果；到1000条停止并引导缩小范围。未知阶段事项计入无阶段筛选的统计并提示，不误当成看板空列。
- 按 key 去重、记录最早读取时间，补齐结束再次校验代理代次和数量。Jira 6 分页不是事务快照，外部同时修改仍可能产生未检测到的变化。

## 代理调度、缓存和失效

`server/jira-scheduler.mjs` 管理总并发、优先级、取消和队列上限。顺序为写入、当前页面读取、后台统计；已发出的请求不抢占，响应体读取完毕才释放槽位。

`server/read-cache.mjs` 按登录 sid 和完整 URL 隔离缓存。相同请求在执行中始终共享 Promise，成功完整响应后起算 TTL；401/403/429/5xx、非 JSON、解析失败和取消不进入成功缓存。多个 HTTP 调用方直接等待同一结果，不再使用202和每250毫秒重复询问。

一个共享消费者取消不影响其他消费者，全部离开才中止上游；排队的过期请求可移除。当前版本不自动重试 Jira 请求，失败保留实际错误并由用户重试，写入也不自动重试。

`server/index.mjs` 的 `readJira` 统一 HTTP/MCP 的读取；写入共用 Jira 调度与 `invalidateJira`：

1. 明确成功的写入，让相关项目的搜索和问题详情失效，保留无关项目和元数据；跨项目链接处理两端。
2. 无法确定项目、查询包含顶层 OR 等情况，保守扩大失效范围。
3. 明确4xx错误保留缓存；5xx、超时、网络断开等写入结果不确定时先失效，不盲目重试。
4. 请求开始记录数据代次。若读取期间发生写入，返回409要求重载，旧结果不能重新进入有效缓存。
5. 当前页面写入成功后刷新可见看板与统计；其他页面、MCP、其他标签页的修改，在重新进入、窗口聚焦或手动刷新时通过本机代次发现。直接在 Jira 修改则通过过期同步获知。

当前未做卡片的乐观移动或单条回读补丁；使用当前范围重新核对计数和归属，避免猜测更新。

## 省略文字提示

`FullTextTooltip` 提供全局单一浮层。子项、关联问题、所属需求、看板卡片、表格标题/被截断单元格、版本标签等可悬停查看全文，键盘聚焦同样可触发；浮层可移入、选择复制，支持 Esc 关闭、滚动关闭，并避开抽屉裁切与窗口边缘。

## 验证与后续

自动化覆盖调度峰值、后台限制、优先级、队列取消、慢请求合并、成功后起算TTL、错误不缓存、会话隔离、HTTP/MCP共享缓存、跨项目失效、旧读取409保护、人员唯一归属与统计口径。浏览器使用本地模拟 Jira 验证加载、筛选、分页、下钻、全文提示和缓存恢复，不写真实 Jira。

后续可根据实际规模、上游耗时和缓存命中率，决定是否从完整统计数据集直接生成看板；当前仍是分列查询＋单独统计分页。代理已有缓存计数和调度快照，未提供排队耗时/首屏时间的持久化监控或设置面板。
